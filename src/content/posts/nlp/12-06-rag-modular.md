1. **架构跳变**：模块化 RAG——不再拘泥"索引—检索—生成"一条流水线；
2. **流程跳变**：RAG 增强——一次"检索-生成"不够，改成迭代/递归/自适应地跑多轮。

## 三类架构对照

| | 朴素 RAG | 高级 RAG | 模块化 RAG |
|---|---|---|---|
| 流程 | 线性：索引→检索→生成 | 仍是线性，检索前后加优化 | 允许模块**替换与排列组合** |
| 改进方式 | — | 预检索/后检索策略 | 引入功能模块 + 新运行模式 |
| 适应任务 | 通用 | 检索质量不足的场景 | 按任务需求**动态调整**模块交互 |
| 详见 | 主线篇 | 高级 RAG 篇 | 本篇 |

模块化 RAG 的核心词是**灵活性**：模块可换、顺序可变、流程按任务重组，适应性和多功能性超过前两种架构。

## 六个代表性功能模块

这些模块有的是新能力，有的是把高级 RAG 的技巧升格成独立组件：

1. **搜索模块**：不走向量检索，让 LLM 按领域生成代码或查询语言（SQL 等），**直接进入搜索源精确检索**——搜索引擎、维基百科、知识图谱、数据库；
2. **路由模块**：多信息源时，根据查询**规划最优检索路径和策略**（高级 RAG 的查询路由升格为模块）；
3. **融合模块**：对原始查询生成多个不同查询分别检索，**融合检索结果**，形成更深、更全面的参考信息（multi-query 的模块化形态）；
4. **记忆模块**：维护一个动态、无边界的**记忆池**，存原始问题与检索结果，为新输入提供相似记忆片段；
5. **预测模块**：不检索，直接**调用 LLM 生成所需的上下文信息**——少引冗余与不相关内容，代价是内容不再有据可查；
6. **任务适配器模块**：按下游任务**定制专属检索器**。代表 **UPRISE**：轻量检索器从预构建的**提示库**中为当前查询筛选帮助最大的示例。

## 新运行模式

以"引入新模块"为标准看两个代表：

- **Generate-Then-Read**：用**预测模块替换检索器**——先让 LLM 生成与问题相关的上下文（类比 HyDE 的假设文档思路，但生成方就是主模型），再连同问题一起读取作答；
- **Iter-RetGen**：在线性架构上**加迭代流程**，用**记忆模块记录迭代信息**，检索与生成交替推进多轮。

## RAG 增强：一次流程不够，跑几轮？

常规 RAG 只执行一遍"检索-生成"，复杂任务一次跑不出合格结果。三种增强策略：

1. **迭代式 RAG**：基于初始查询 + 迄今生成的文本**反复搜索**知识库，不断累积上下文；
   - 优点：后续生成拿到越来越丰富的参考；
   - 代价：**语义不连续** + **累积不相关信息**（错误滚雪球）；
2. **递归式 RAG**：不断**分解或重写初始查询**，逐层深入检索；
   - 检索器沿递归树拿到更细化的知识，增强的是**深度与相关性**；
3. **自适应 RAG**：引入**反思机制**，模型动态调整处理策略。代表 **Self-RAG**，四步：
   - ① 依据输入**预测是否需要检索**（可以不调检索器）；
   - ② 需要时**并行处理**多个检索文档；
   - ③ 对检索结果**筛选和评估**；
   - ④ 结合合格的检索结果**优化答案选择与生成**，兼顾事实性、流畅性与连贯性。

## 两段式微调体系：检索器和生成器都要调

### 检索器微调（嵌入模型）

- 动机：医疗、法律等专业领域的文本语义分布，与嵌入模型和生成 LLM 的训练语料**差距大**；
- 目的 1：**注入领域知识**，增强语义表示能力；
- 目的 2：**检索器与生成器对齐**——检索"对生成有用"的文档，而不是检索"像问题"的文档。代表 **LSR**（LM-Supervised Retriever）：拿 RAG 系统里 **LLM 生成的结果作为监督信号**回训检索器；
- 轻量替代：微调费资源且不灵活，可以**不动模型、外挂适配器**——**UPRISE** 用预构建提示池为查询配上下文，适配不同任务（同 §2 任务适配器模块）。

### 生成器微调（LLM）

- 目的 1：新专业领域注入领域知识；
- 目的 2：调整**输入输出格式**，让模型适应特定数据格式、按指令生成特定样式响应。
